## 1. Overview

A new e-commerce RAG chatbot for Vietnamese electronics retail, inheriting:
- **From v3:** Supabase/pgvector data layer, 4-stage retrieval pipeline, Google Gemini LLM, PhoBERT NLU, response validation, admin dashboard, data pipeline
- **From itlr:** Query understanding (typo/abbreviation), multi-intent handling, SSE streaming, off-topic gating, engine facade pattern

**Key improvements over v3:**
- Proper Vietnamese BM25 tokenization (pyvi)
- Thread-safe engine initialization
- Conversation memory (multi-turn)
- Streaming chat support
- Off-topic rejection
- Multi-intent compound query handling

## 3. Engine Facade

Single `Engine` class — thread-safe initialization, clean API for all request handlers.

```python
class Engine:
    def __init__(self, settings: Settings):
        self.settings = settings
        self._lock = threading.Lock()
        self._ready = False
        self.nlu = None
        self.nlu_phobert = None
        self.retriever = None
        self.recommender = None
        self.llm = None
        self.off_topic = None
        self.session_store = None

    def _warmup(self):
        with self._lock:
            db = get_db_pool(self.settings)
            self.nlu = RuleEngine()
            self.nlu_phobert = PhoBERTNLU()
            self.retriever = Stage01Retriever(db, self.settings)
            self.recommender = ProductRecommender(db)
            self.llm = LLMClient(self.settings)
            self.off_topic = OffTopicGate(self.retriever.embeddings)
            self.session_store = SessionStore(ttl=self.settings.SESSION_TTL)
            self._ready = True

    def chat(self, query: str, session_id: str = None) -> dict: ...
    async def chat_stream(self, query: str, session_id: str = None): ...
    def search(self, query: str, top_k: int = 5) -> list[dict]: ...
    def parse_nlu(self, query: str) -> dict: ...
```

Startup: background thread calls `_warmup()`. Routes check `_ready` → 503 if not.

## 4. Chat Pipeline Flow (8 Steps)

```
User Query
  │
  ▼
[Step 1] Query Understanding — typo correction, abbreviation expansion, accent normalization
  │
  ▼
[Step 2] Off-Topic Gate — embedding similarity < 0.48 → reject
  │
  ▼
[Step 3] Multi-Intent Split — split on commas/semicolons/"và", resolve subjects
  │
  ▼
[Step 4] NLU — Rules-first (regex intent + NER), PhoBERT fallback if confidence < 0.45
  │
  ▼
[Step 5] Conversation Memory — load last 6 turns, resolve references ("cái đó")
  │
  ▼
[Step 6] 4-Stage Retrieval — Stage 0 filters → Stage 1 hybrid → Stage 2 rerank → Stage 3 MMR
  │        + Product Recommender
  ▼
[Step 7] LLM Generation — Gemini with RAG prompt, or template fallback
  │
  ▼
[Step 8] Response Validation — price/name grounding check
  │
  ▼
Response JSON: { answer, intent, confidence, entities, products[],
                  recommendations[], corrections[], warnings[], session_id }
```

**Streaming variant:** Steps 1-6 sync, Step 7 yields SSE chunks, final `meta` event with products/warnings.

## 5. NLU Design

**Rule Engine** (`nlu/rule_engine.py`):
- Accent-stripped Vietnamese regex matching
- Dictionaries: brands, models, specs, price patterns
- 11 intents: ask_specs, compare_products, ask_price, ask_warranty, purchase_consultation, ask_promotion, order_product, complain, general_query, out_of_scope, greeting
- Confidence proportional to match specificity (not fixed per intent)
- Greeting priority: checked first, skips other intents

**PhoBERT Fallback** (`nlu/phobert_nlu.py`):
- `souta04/phobert-electronics-e-commerce-nlu` from HuggingFace
- Only runs when rule engine confidence < 0.45
- Intent classification only — NER always from rules
- Falls back to rules if model fails to load

**Query Understanding** (`nlu/query_understanding.py`):
- Typo correction: fuzzy match against brand/model/spec vocabulary
- Abbreviation expansion: common Vietnamese tech abbreviations
- Accent normalization: handle typing without diacritics
- Returns correction notes for response prefix

**NER Entity Types:**
| Type | Examples | Method |
|------|----------|--------|
| PRODUCT_NAME | iPhone 15, Galaxy S24 | Dictionary + fuzzy |
| BRAND | Apple, Samsung, Asus | Dictionary match |
| MODEL | TUF Gaming, Pro Max | Dictionary match |
| PRICE | 15 triệu, dưới 20tr | Regex patterns |
| SPEC | RAM 16GB, SSD 512GB | Regex patterns |

## 6. Retrieval Pipeline

**Stage 0 — Hard Filters:** SQL WHERE clauses for category, max_price, use_case from NER entities.

**Stage 1 — Hybrid Scoring:**
```
score = 0.50 * BM25 + 0.30 * pgvector_cosine + 0.10 * budget_fit + 0.10 * rating_norm
```
- BM25: pyvi tokenizer (fixed from v3's broken regex split)
- pgvector: BGE-M3 (1024-dim), cosine distance on product_chunks table
- Budget fit: `1.0 - abs(price - target) / target` when price entity detected
- Rating: normalized product rating

**Stage 2 — Cross-Encoder Reranking:**
- `cross-encoder/ms-marco-MiniLM-L-6-v2` on top-20 candidates
- `0.60 * CE_score + 0.40 * stage1_score`, sigmoid normalized

**Stage 3 — MMR Diversity:**
- Lambda = 0.7, uses pgvector chunk embeddings averaged per product

**Product Recommender:** TF-IDF + category bonus + spec Jaccard + price proximity + rating. Cold-start trending fallback.

**BM25 Fix:**
```python
# Before (v3 — broken):
def tokenize(text): return re.findall(r'\w+', text.lower())

# After (new — proper Vietnamese):
from pyvi import ViTokenizer
def tokenize(text): return ViTokenizer.tokenize(text).lower().split()
```

## 7. LLM Client & Prompting

**LLM Client** (`chatbot/llm_client.py`):
- Google Gemini via `google-generativeai` SDK
- Temperature actually passed to API (fixed from v3)
- Streaming via `stream=True`
- Template fallback per-intent when Gemini unavailable

**System Prompt:**
- Persona: Vietnamese sales staff, "em" / "anh/chị"
- Brevity: 2-4 sentences or 3-4 bullet points
- Strict grounding: only retrieved product data
- No internal jargon (never mention "NLU", "RAG")
- Open-ended closing question
- Intent-specific formatting guidelines

**RAG User Prompt:**
```
[DỮ LIỆU SẢN PHẨM TRUY XUẤT]
{product context: name, brand, category, price, rating, specs (250 char limit)}

[THÔNG TIN PHÂN TÍCH NLU]
Intent: {intent} | Entities: {entities}

[LỊCH SỬ HỘI THOẠI]
{last N turns if available}

[CÂU HỎI CỦA KHÁCH HÀNG]
{original or reference-resolved query}
```

## 8. Streaming & Multi-Intent

**SSE Streaming:**
- Steps 1-6 sync (<500ms), Step 7 yields `data: {"type":"text","content":"..."}` chunks
- Final event: `data: {"type":"meta","intent":...,"products":...,"warnings":...}`
- Done: `data: {"type":"done"}`
- Client: EventSource or fetch + ReadableStream

**Multi-Intent:**
- Split on commas, semicolons, "và", "và cũng", "ngoài ra"
- Subject-less clauses inherit from preceding clause
- Each clause routed independently through NLU
- Response: merged with ## section headings
- Fallback: treat as single query if splitting fails

## 9. Off-Topic Gate & Validation

**Off-Topic Gate** (`core/off_topic.py`):
- Max cosine similarity between query embedding and all product chunk embeddings
- Threshold: 0.48 (configurable)
- Returns early before NLU/retrieval

**Response Validation** (`chatbot/validator.py`):
- Price grounding: LLM-mentioned prices vs context prices (5% tolerance)
- Product name grounding: LLM-mentioned names must exist in context
- Warnings appended to response JSON, not blocking

**Query Corrections:**
- Friendly prefix: "Em hiểu anh hỏi về: **MacBook Air** (viết tắt: **mba**)"
- Only shown when corrections happened

## 10. Session & Conversation Memory

```python
class SessionStore:
    def __init__(self, ttl=1800, max_turns=6):
        self._sessions: dict[str, list[dict]] = {}
        self._last_access: dict[str, float] = {}

    def add_turn(self, session_id: str, role: str, content: str): ...
    def get_history(self, session_id: str) -> list[dict]: ...
    def resolve_reference(self, session_id: str, query: str) -> str | None: ...
```

- In-memory with TTL expiry (30 min default)
- Max 6 turns per session
- Reference resolution: "cái đó", "sản phẩm đó" → last mentioned product
- Optional: omit `session_id` for stateless requests

## 12. Configuration

All settings from `.env` via pydantic-settings, cached with `@lru_cache`.

Key settings: `GEMINI_API_KEY`, `GEMINI_MODEL_NAME`, `DB_*`, `EMBEDDING_MODEL`, `TOP_K`, `RERANK_TOP_K`, `MMR_LAMBDA`, `NLU_CONFIDENCE_THRESHOLD`, `OFF_TOPIC_THRESHOLD`, `SESSION_TTL`, `SESSION_MAX_TURNS`, `HOST`, `PORT`.

All retrieval weights configurable (were hardcoded in v3).

**Dependencies:** fastapi, uvicorn, python-dotenv, pydantic-settings, psycopg2-binary, google-generativeai, sentence-transformers, rank_bm25, pyvi, numpy, scipy.

## 13. What We're NOT Building (YAGNI)

- No collaborative filtering (v3 didn't need it for e-commerce)
- No OpenAI/Ollama dual LLM (Gemini only + template fallback)
- No FAISS/hnswlib ANN (pgvector handles it)
- No synthetic data generation (use v3's real Supabase data)
- No learning-to-rank / CF evaluation (different domain)
- No opencode CLI integration (orphaned in itlr)
